No other change is open (`openspec/changes/` holds only `archive/`), so there is no archive order. The change is one branch and one PR with its plan; `openspec archive` is a separate PR after the merge.

No unit test reaches `GedcomView`, `main.ts` or `DeskViews.ts` (`obsidian` is types only in Vitest). Each task that touches them applies what an earlier task tests, and is covered by the harness specs in group 8 and the manual check in 10.2.

Run `npm run test` before touching anything: 1084 tests in 64 files pass on `main`. A new worktree needs `rm -rf node_modules && npm ci` before the first `npm run check`.

**Order.** Every task keeps `typecheck`, `lint` and the tests green, so that each group ends with `npm run check` exiting 0. Strings and the pure layer come first (1–3), then settings (4), the shared parts the board needs (5), the board in small modules (6), and only then the mode is registered (7): adding `"map"` to `DESK_MODES` breaks every `Record<DeskMode, …>` (`MODE_LOOKS` in `deskState.ts`, `SHOW_NAMES` in `commands.ts`) and so cannot come before the things they point at. Then styles, harness and specs (8), documents (9) and the gate (10).
