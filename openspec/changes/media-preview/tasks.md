## 9. What the code review found

- [x] 9.1 Stop the frame stretching the image: `.gedcom-media-frame` is not a flex container, and a cropped `<img>` is positioned from the frame's corner and moved by `transform` rather than by a negative margin. A flex line stretched the image to the frame's height minus that margin, so the rectangle was measured against a size the image never had and every cropped preview showed the wrong part of the picture — verify in `tests/mediaPreview.spec.ts` against a fixture painted red only inside the rectangle: the region on screen is the rectangle in source pixels, and all four corners of the frame sample red.
- [x] 9.2 Stand the record preview aside only for a gesture the media preview answers, in `src/editor/composition.ts` — verify in `tests/mediaPreview.spec.ts` that an `OBJE` pointer shows the record when media preview is off, and when media preview asks for a modifier the event does not carry, while a modifier gesture with media preview on still shows the picture alone.
- [x] 9.3 Scale a rectangle larger than the bound instead of clipping it: `cropScale(crop, bounds)` in `src/editor/media.ts`, applied to the frame's size and the image's transform together — verify in `src/editor/media.test.ts` that the factor is the tighter of the two dimensions, never above 1, and 1 for a rectangle with no extent, and in `tests/mediaPreview.spec.ts` that a 1200×900 rectangle is shown whole, inside the bound and undistorted.
- [x] 9.4 Close the popover being replaced: `showPreview` and `showMediaPreview` in `src/GedcomView.ts` hide before they show, the pointer moving between two positions asking to show without asking to hide. The harness was already doing this in `showMedia`, which is why no spec could see it.
- [x] 9.5 Give the `<img>` an `alt` — the caption where the author wrote one, the file name otherwise — and answer a file the renderer cannot draw with the not-found row rather than an empty frame — verify in `tests/mediaPreview.spec.ts` with bytes no decoder accepts.
- [x] 9.6 Hold the hover's rest timer per view rather than per extension instance, in `src/editor/mediaPreviewHover.ts`, so one document open in two panes cannot cancel the other's wait, and take the window from the view — a popout has its own.
- [x] 9.7 Mount the harness with the shipped defaults instead of its own `"modifier"`, in `harness/mount.ts`, so a spec that names no trigger exercises what a reader gets; the specs about the modifier gesture in `tests/hover.spec.ts` now name it.
- [x] 9.8 Say in `styles.css` why a reference in a rendered note keeps the property colour the editor no longer gives it: nothing in a note goes anywhere on a click, so nothing there should promise one.

- [x] 9.9 Let the popover take the size of what it holds — a `gedcom-media-popover` class on the `HoverPopover`'s element, `width: fit-content` in `styles.css` — and stop the frame hiding anything but a rectangle, so a picture wider than a popover's own `--popover-width` is scaled rather than cut off at its right edge. Reported from the vault against a landscape `FILE`; add Obsidian's `.popover.hover-popover` box to `harness/palette.css` first, without which a harness popover shrink-wraps its content and no spec can see it — verify in `tests/mediaPreview.spec.ts` with a 1600×400 image and an 800×200 rectangle of it that all of what is drawn falls inside the popover, and that the whole rectangle is still the region on screen.
- [x] 9.10 Bound the picture rather than the box: `box-sizing: content-box` on `.gedcom-media-preview`, the padding otherwise coming out of the room a rectangle measured against the bound needs — verify by the same specs, which are short of the rectangle by exactly the padding without it.
