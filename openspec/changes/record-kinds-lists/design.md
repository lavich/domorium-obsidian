## Context

This plan was first written against `main` and is now built in branch `lavich/record-fields-tree`, on top of the change of that name, and archived after it. What the branch's code does today, as far as this change touches it:

- The list (`src/desk/listRows.ts`, `src/desk/fileList.ts`) has four kinds, `people`, `families`, `sources`, `places`: `ListKind`, `LIST_KINDS`, `COLUMNS`, `cellsOf`, `sortValue`, `listRows`, the label tables of `fileList.ts`, `countLabel`. `recordKind(index, xref)` answers a kind for a person, a family, a source and a place, and `listSelection` passes on only what `recordKind` knows. `ListBoard.place()` keeps the Places against a selection of another kind that did not come from the card (`this.kind === "places" && kind !== "places" && !fromCard`); `activate()` selects `row.xref ?? placeId(key)`. People, families and sources are searched by lower case only; places through `foldText`.
- The header row's cells are made once, in the constructor, from `columnsOf("people")`, and relabelled per kind; a kind therefore has at most four columns. Media has exactly four, the other new kinds fewer, and `drawHeaders` hides the cells a kind does not use, as the Places (three) already need.
- `resized()` decides the compact layout from the root's width with `COMPACT_BELOW` (640) and `WIDE_FROM` (680), from a `ResizeObserver` on the root and on a probe row; nothing measures the kind buttons, which simply shrink.
- The read model (`src/genealogy/build.ts`) walks the top-level symbols once per revision; it keeps `declared` (every symbol with an identifier) for `record(xref)`, `objects` for `media(xref)`, and `repositories`, which `sourceRowOf` reads for the sources' Repository column (`readSourceRow(record, repositories)`). `collectMediaLinks` reads a record's own `OBJE` lines (level 1) only. `recordLines` gives a root a text only for `NOTE` and `SNOTE`, from the symbol's `label`; the document symbols carry no label for any other record, so a custom record's own value (`0 @P1@ _PLAN Custom value`) is not in them. `IndexSource` is `getDocumentSymbols` and `readDate`, and the index reads everything it needs during its pass so that it never holds a service that has moved on.
- `pageKind` (`src/desk/deskState.ts`) answers `person`, `family`, `source`, `media`, `place`; `PageKind` has no `event` any more. It decides what a link selects (`routeLink`, `GedcomView.goToXref`, `goToRecord`), what the cursor selects (`GedcomView.has()` into `shouldFollowCursor`, `TabModes.setMode` on leaving Source), what `TabModes.select` accepts and keeps (`textChanged`), and what `renderPointer` draws as a link. `shownRange` reads people, families, sources and media.
- The card (`src/desk/recordCard.ts`) has no header bar and no history. `drawRecord` builds the `PageHost`, works out `writes` from `tab.version()` and `tab.describes(opening)`, sets `uneditable` where the tab writes but this record cannot, and draws person, family and source through `drawTree` (`personPage.ts`), media and place through their own pages. `hasTree` is person, family or source. The announcement uses a private `recordName`; `mediaPage.ts` has another; `lineView.ts` has `recordTitle`, which the tree uses for pointers and the root's summary. The empty state is `card.empty` when the file has no people, families or sources.
- `renderPointer` (`src/desk/detail/lineView.ts`) draws a pointer to a shared note as the note's text and lines and returns; any other pointer is a link where `pageKind` answers and plain text otherwise. So a `REPO` line in a source's tree is plain text today, and becomes a link with no change of its own once `pageKind` answers for a repository (checked in the code; the tree calls `renderPointer` for every pointer row, `tree.ts` `paintValue`).
- `GedcomView.selectRecord` places the cursor in Source at `records().find(identifier === xref).start`, which the header, having no identifier, never matches. `goToRecord` selects only a record with an identifier that `pageKind` knows.

## Goals / Non-Goals

**Goals:** every record a file declares, except its trailer and records without an identifier, can be found in the list and opened on a card that is its tree; adding a kind follows the pattern the places set.

**Non-Goals:** selecting the new records by the cursor; marking them in the graph or the timeline.

## Decisions

**The kinds and their rows.** Eight kinds: `people`, `families`, `sources`, `places`, `media`, `notes`, `repositories`, `other`. A record belongs to exactly one. `other` lists the header first, under the synthetic id `header:` (`HEADER_ID` in `deskState.ts`, as a place has `place:`), then, in file order, every top-level record with an identifier whose tag no other kind takes: `SUBM`, 5.5.1 `SUBN`, a custom tag, and any record of the standard no kind lists. `TRLR` and records without an identifier are not listed (M4). The header's row carries `header:` as its `xref`, so `keyOf`, `markedKey`, `activate` and `place` treat it as any record.

**Columns.** Media: Title, File, Format, Linked from. Notes: Text, Linked from. Repositories: Name, Address, Sources. Other: Kind, Name, Linked from. New `SortKey`s: `text`, `file`, `format`, `address`, `kind`, `linkedFrom`; `title`, `name` and `sources` are reused, `sortValue` dispatching by kind as now. Under any sort the header row stays first and the sort orders the rest (M4).

**Linked from counts records, not lines (S5).** It is the number of distinct records — the header among them — with at least one line, at any depth, whose payload is a pointer to the record; a record pointing at itself, `@VOID@` and a `CONT` or `CONC` line do not count. Records, because the Sources' *Cited by* already counts records (`citingRecords` takes a `Set`), so the two numbers of one list mean the same thing, and because a person who cites a note twice is still one place to look. The repositories' **Sources** is the same count restricted to source records.

**The media card has no list of its own to agree with.** It was written first that the media card's *Used by* (`media.links`, a record's own `OBJE` lines) and the list's *Linked from* (any pointer, at any depth) could differ. Since 2026-11-12 the media card is a tree and has no *Used by*; *Linked from* is the one count.

**The counts are a new deep walk, lazy, once per index (M1).** The existing pass reads only the top-level symbols and, for citations and media, a few known tags; no pass today sees every pointer. `build.ts` keeps the top-level symbols in its closure and, on the first `linkedFrom` or `sourcesOf` call, walks every line of every record once into a `Map<string, Set<string>>` (target → pointing records), kept for the index. Lazy rather than eager, because a reader who never opens these kinds or their columns pays nothing, and the walk is one per revision either way; the people of a 20 000-person file are not delayed. Which records each kind holds is read eagerly in the existing top-level loop (a symbol per record, no conversion); a row's texts are converted on first request and cached, as `record(xref)` already is.

**A custom record's own value comes from the language service (S1).** Probed on the linked upstream (lavich/domorium main 9409dd7): `describeStructure({line, character: 0})` on `0 @P1@ _PLAN Custom value` answers `value: "Custom value"`, `extension: true`, while its document symbol has no `label`. `IndexSource` gains `describeStructure`, and `buildIndex` calls it during its pass for each top-level record of the Other kind whose tag is not a note's, keeping the value in the record's entry; `recordLines` puts it on the root as `text`. Read in the pass, so the index still holds no service. A refusal (`no-dialect`) leaves the value out. Shared notes keep reading their text from the symbol's `label` and their `CONC`/`CONT` lines, as now.

**One naming function (S3).** `recordTitle(index, xref)` in `lineView.ts` becomes the only one: the list's first text column (Title of media, Text of notes, Name of repositories and other records), the card's announcement (replacing `recordName` in `recordCard.ts`), pointer link text (already), and the tree root's closed summary (already); `mediaPage.ts`, which had a namer of its own, is gone with the media card's form. It adds: a place by name; a medium by title, else the base name of its first file; a note by the first non-empty line of its joined text — the `RecordLine` text, which `recordLines` builds from the label and the `CONC`/`CONT` lines, not the symbol's label (M1); a repository and a submitter by `NAME`; any other record by `NAME`, `TITL`, its own value (above), the first child value, else its kind as the tree labels it; `header:` as *File header* (`record.header`). The pointer to a shared note is the exception to "the pointer's text is the name": `renderPointer` draws the note's whole text inline, as `record-fields-tree` has it (M3).

**Search (M5).** Each new kind searches what its row shows, the note its whole joined text, the other records their kind both in the reader's words and as the tag is written. The four new kinds fold through `foldText`, as the places do: notes are free prose in any language and a repository's address is a place. The people, families and sources keep their case-only match; changing them is not this change's (Non-goals). Strings: `list.search.media` "Title, file, format…", `list.search.notes` "Text of the note…", `list.search.repositories` "Name, address…", `list.search.other` "Kind, name…", and `list.nothing.*` saying the same.

**Counts are digits (M2).** `fill` in `src/i18n/index.ts` writes `String(count)`; the existing counts read `17 people` and a large file `20000 people`. The scenarios read `1478 notes`; grouping digits by locale is a change for every kind, not this one.

**Eight kinds, and a dropdown measured, not a breakpoint (S4).** `fileList.ts` keeps, beside the visible bar, a hidden probe of the eight buttons (`aria-hidden`, out of the flow, the same classes), so their natural width is measurable while the dropdown is shown. `resized()`, already called by the `ResizeObserver` on the root, reads the probe's width and the search icon's, and switches to the dropdown when the bar is narrower than their sum, back to buttons only when it is wider than the sum by `KINDS_MARGIN` (40 px, the gap `COMPACT_BELOW`/`WIDE_FROM` already use), so a width at the edge does not flap. The probe is measured again on every resize, which also covers a change of language or font size. The dropdown is a `select.dropdown` named by `list.kind` ("Kind of records"), placed where the buttons were in the tab order, 44 px on touch through the rules the sort select already has. Alternative: a container query. Rejected by the user: the width the buttons need depends on the language and the font.

**Keeping the kind against a person from outside (B1).** `place()` generalises the Places rule, keeping its order — the keep rule, then `if (!reveal) mark and return` — so a selection that does not reveal (the cursor in Source) switches the kind when the list is next shown and calls `select(…, reveal = true)`, which the spec now says (M4): while the list shows `places`, `media`, `notes`, `repositories` or `other`, a person, a family or a source selected from outside (`!fromCard`) marks nothing and does not switch the kind; a record of any of those five kinds switches to its own kind and is brought into view, from anywhere; a record pressed in the card switches as today. `recordKind` and `listSelection` answer the new kinds (S1), so a selected note, repository or other record stays marked and is brought into view.

**One page kind for the new cards: `record`.** `pageKind` answers `record` for a shared note, a repository, a submitter, a submission, a record of the file's own and `header:`. `followsCursor(index, xref)` is true for a `person`, `family`, `source` or `media` page kind only, and `GedcomView.has()`, `cursorSettled` and `TabModes.setMode` ask it instead of `pageKind`. The cursor in Source thus keeps selecting what it selects today; note that today that includes a multimedia record, which the user described as "people, families and sources (as today)"; the plan keeps today's behaviour and flags it.

**The new cards are trees (`src/desk/recordPage.ts`).** `renderRecordPage` calls `drawTree` with no facts, as `renderSourcePage` does; `hasTree` includes `record`, so these cards take the tree's header bar, a slot of the session's twenty and a remembered scroll. The root is labelled by `tagLabel` of the opening tag; `record.tag.HEAD` (*Header*) and `record.tag.SUBN` (*Submission*) are added to both catalogues (M4). `recordLines` gives a root a text for a note (from the symbol) and for a custom record (from the index's described value, above), and the tree shows the root's value: a note's text as a note (folded, an editable prose field where the card writes), anything else as a field.

**A record's own value is written through `setValue` on its opening line: a dependency on lavich/domorium#527.** The user chose on 2026-11-11 to wait for upstream rather than make the value read-only. The field of a root — a shared note's text, a 5.5.1 note record's text with its `CONC`/`CONT`, a custom record's value — commits through the same `setValue(at, { value }, version)` path as any line, `at` being the opening line; the service writes the payload and its continuation lines and keeps the lines beneath (a `SOUR` under a note). Whether a root has a field is the service's to say, as for any line: the tree draws one only where `describeStructure` of the opening line describes a payload (`payload.kind` other than `none`; probed on the linked upstream, `HEAD` and `INDI` answer `none`, `SNOTE` and `_PLAN` answer `text` with their `value`), and a record that holds no value by the standard has no field. With #527 a write the standard does not allow comes back as its own refusal (`value-not-allowed` in the issue) and is shown as every refusal, in the plugin's words under `edit.refusal.<code>`. The service linked today describes the opening line but refuses `setValue` there with `record-edit-unsupported`; this is the dependency, not something the plugin works around — the change is not merged until a release carries #527, and the browser and unit tests of the field run against the linked upstream that has it. The header's root has no field because the service describes `HEAD` with no payload (`value-not-allowed` on a write), as it does `INDI`.

**Every new card edits, the header's included (2026-11-12).** The first plan kept the header read-only, since changing `GEDC.VERS`, `CHAR` or the schema from a field rewrites how the whole file is read. The language service now answers for that itself: it describes `HEAD` (7.0: `COPR DATE DEST GEDC LANG NOTE PLAC SCHMA SNOTE SOUR SUBM`; 5.5.1 also `CHAR`, `FILE`, `SUBN`), checks the header's values, refuses changing `GEDC.VERS` or removing `GEDC` with `rule-violation` and removing `CHAR` with `required-field-missing`, and the user chose «да». So `drawRecord` has no gate for `header:`: `writes` and `uneditable` are worked out as for any record. No rule of the plugin's own guards `CHAR`; if one is wanted it is upstream's. A submitter and the other records edit within what `describeStructure` describes, which is the existing rule for every tree; a custom record is described with `extension: true` and keeps its fields and removals and no menu, as a custom line does.

***Open note* (B2, M1).** `renderPointer` is unchanged and keeps drawing a shared note's text and lines inline. The control is drawn by the tree, in `paintValue` right after `renderPointer`, as `placeControl` draws a place's: a `div.clickable-icon` made `pressable` (role `button`, `tabindex` 0, Enter and Space), named `desk.openNote`, focus key `t:<node key>:note`, whose click stops propagation, so a press does not toggle the node through the header's own click, and calls `host.openRecord(xref)` — a card-origin selection, which does not expand the sidebar and switches the list to the Notes. A pointer row with nothing beneath it is a line and shows the control at once; a pointer with lines beneath it (a citation) is a node, closed at first, whose summary reads the note's first line with no control, and the control appears once the node is opened, where the value is painted. One control at a time, as the missing pointer's *Show in source* is. Alternative: the control in the closed summary as well. Rejected: the summary is a single line the panel cuts, and the open row is one press away. A pointer to a repository or a submitter is a link through `renderPointer` once `pageKind` answers `record`, with no other change.

**The routing is one pure function (S4).** `deskState.ts` gains `routeRecord(index, target, declared, interfaceOn)`, where `target` is a link's identifier or a *Go to record* entry, answering `{ to: "select", id }` (a record that has a card while the interface is on, `header:` for `HEAD`), `{ to: "source", at }` (a record without a card, or any record while the interface is off: its start) or `{ to: "nowhere" }`, and `followsCursor(index, xref)` for the cursor's rest and for leaving Source. It replaces `routeLink` and the decisions inside `goToXref`, `goToRecord` and `has()`; `GedcomView` only applies the answer. Tested in `deskState.test.ts`, so nothing of the routing is left to a check by hand.

**Source mode (S2).** `shownRange` reads `index.record(xref)?.range` for `record` kinds and the header's range for `header:` (`index.record(HEADER_ID)`), so switching to Source puts the cursor at the selected note, repository, submitter, other record or header. `GedcomView.selectRecord` places the cursor from `shownRange(...).start` instead of looking the identifier up in `records()`, so a link or *Go to record* to the header in Source puts the cursor on `0 HEAD`.

***Go to record* on the header opens its card (M8).** `routeRecord` answers `header:` for a `GedcomRecord` whose tag is `HEAD`; the trailer and records without an identifier still go to Source. Copying a link is offered for any selected record with an identifier; the header and a place offer none, as `identifiedRecord` already decides.

**Empty state (M7).** `card.empty` is shown when the file declares no record with an identifier at all; a file of notes alone says to select a record. The header alone does not count, so a file with nothing but `HEAD` and `TRLR` still says it holds nothing to show.

**Phone and compact rows (S6).** Two lines per row, as the existing kinds: media — title and count / file · format; notes — text over both lines (`-webkit-line-clamp: 2`), count at the end of the first; repositories — name and count / address; other — name and count / kind. `countLabel` gains `linkedFrom` (`list.compact.linkedFrom`, "Linked from {count}", as `citedBy` reads) and reuses `list.compact.sources` for the repositories' Sources.

**The header row's Linked from is blank (M5).** Nothing can point at a record with no identifier, so the cell is empty rather than `0`, and the header sorts first regardless.

**Large files (S7).** The Gramps export is not in the repository, so `tests/generated.ts` gains `generatedNotes(count, dialect)`: a 7.0 file of `count` `SNOTE` records and a 5.5.1 file of `NOTE` records continued with `CONC` and `CONT`, each pointed at by a person; the timed Playwright test uses 1478 notes and asserts a loose bound — the first rows drawn within 1000 ms of choosing Notes in headless Chromium — and a unit test checks that the walk runs once for all counts of a revision.

## Decisions of 2026-11-12: the header, the media card and the file of a medium

**The media card is a tree.** `pageKind` already answers `media`; `hasTree` takes it, and `drawRecord` draws a multimedia record through `renderRecordPage` like a note, so the media card has the tree's header bar, a slot of the session's twenty and a remembered scroll, and edits through the same `writes` gating. The root is labelled by `tagLabel("OBJE")`, *Media*, and has no value field (`OBJE` holds none). It has no heading and no *Used by*: the cards of the other kinds have neither, and the list's *Linked from* says how many records point at the medium. `mediaPage.ts` and its test go, with `renderTile` (its only caller; checked: no tile is drawn in the graph, the timeline, the list or a popover, which draw media through `src/editor/`), the strings only they used (`desk.mediaPage`, `desk.usedBy`, `desk.usedByNone`, `desk.notInVault`, `desk.fromWeb`, `desk.notAnImage`, `mediaKind.*` where nothing else reads them) and their CSS. `drawPicture` and `MediaItem` stay in `media.ts`, the row of a file uses them. In the read model `MediaRecord.links`, `MediaRecord.at` and `collectMediaLinks` have no caller left and go; the read-model requirement on multimedia records is restated without them. The portrait a person's model carries is not touched: it does not depend on the media card.

**The row of a medium's file.** A `FILE` line whose parent is `OBJE` — the `1 FILE` of a multimedia record, or a 5.5.1 inline `2 FILE` beneath a record's `1 OBJE` — is drawn by the tree as a **file control** instead of a text field: the picture, where the language service's media reference resolves to an image the card can draw (`mediaItemAt`, a vault image through `resolveVaultResource`, or an `https` image while remote images are allowed by the setting), and otherwise a file icon and the path as written. `HEAD.FILE` in 5.5.1 names the transmission, not a medium, and stays a field. The tree asks `host.mediaFileAt(line)`, which `drawRecord` answers through the tab's existing `mediaItem(at)`; `at` is the position of the line's value, which `recordLines` now keeps on a line with a text payload as `valueAt` (from the symbol's tag, as `payloadPosition` already reads it for media), because `getMediaAt` answers only on the value. The control is a `div.clickable-icon` made `pressable` (role `button`, Enter and Space), focus key `t:<key>:file`, named *Change the file {name}* where the card writes and *Open {name}* where it does not; on a coarse pointer and `.is-mobile` it is at least 44 pixels in each direction. The picture is at most 160 px tall and as wide as the row allows.

**Pressing it.** Where the card writes, pressing the control opens a menu at it (`chooseField`, the Obsidian `Menu` the add menu uses, at the control when the keyboard opened it) of two entries with icons, *Choose from the vault* (`folder-open`) and *Upload from device* (`upload`). Where the card does not write — a file with no dialect — the control opens the file in Obsidian, as the old media card's picture did, and is not a button where the file is not in the vault. Opening the file from a writing card is not offered: the user asked for the press to offer another file (Non-goals).

**Choose from the vault.** A `FuzzySuggestModal` (`VaultFileModal`, in `pointerModal.ts` beside the list of records) of every file of the vault except GEDCOM files — every file rather than images only, because a medium may be a sound, a film or a document — images first, then the rest, each part in path order, the file the line names now marked ✓; typing searches every one by its path. Choosing one writes its path. Nothing is copied.

**The path written.** `fileTarget(documentPath, vaultPath, dialect)` in `mediaFile.ts` is `encodeFileTarget(relativeFilePath(documentPath, vaultPath), dialect)`, the spelling moved media get in `movedFiles.ts`, kept only where `resolveFileTarget` reads it back as the same vault path, as `readsAs` checks there. A 7.0 file names only files in its own folder or beneath it (`resolveFileTarget` reads `..` as a name); the service accepts `../x.jpg` for a 7.0 `FILE` (probed), so a file the path cannot reach is declined by the plugin, before anything is written or copied, with its own refusal code `file-out-of-reach`, worded in both catalogues under `edit.refusal.*`. 5.5.1 reaches a file above its folder with `..`.

**The format.** Where the `FILE` line states a `FORM` beneath it, the same change writes the new file's format: in 7.0 a media type — the type the device gives an uploaded file where it reads as `type/subtype`, else the one its extension names in a small table (`jpg`/`jpeg` `image/jpeg`, `png`, `gif`, `webp`, `svg` `image/svg+xml`, `bmp`, `tif`/`tiff`, `avif`, `heic`, `mp3` `audio/mpeg`, `wav`, `ogg`, `m4a` `audio/mp4`, `mp4`, `webm`, `mov` `video/quicktime`, `pdf`, `txt`), else `application/octet-stream`; in 5.5.1 the extension in lower case, `jpeg` as `jpg` and `tiff` as `tif`. Probed on the linked upstream: 7.0 `FORM` takes any `type/subtype` and refuses `png` (`payload-datatype`); 5.5.1 `FORM` takes only `bmp gif jpg ole pcx tif wav` and refuses `png` (`value-not-in-enum`). The service is the rule: a 5.5.1 file whose `FORM` cannot take the new file's extension refuses the change, and nothing is written. Where no `FORM` is stated, none is added (Non-goals).

**One change.** `mediaFileEdit` asks the service for `setValue` on the `FILE` line and, where there is one, on its `FORM`, both at the version the card was drawn at, and joins the two edits into one `WorkspaceEdit`: they are on different lines (the `FORM` is beneath the `FILE` and after its continuation lines), so they never overlap, and the tab applies them as one step of Source's history, undone at once. If either is refused, the refusal of the first is shown and nothing is written. FILE first and FORM second is therefore not needed.

**Upload from device.** `chooseDeviceFile` opens an `<input type="file">` (`deviceFile.ts`: made in the document, hidden, clicked from the menu's press so the device's picker may open, removed once it answers or is cancelled), which works in the desktop app and in the mobile one. The chosen file is copied into the vault, never elsewhere:
- **The folder** is the folder of the file the line names now, where it resolves to a file in the vault; otherwise a folder `Media` beside the GEDCOM file (`Media` at the vault's root for a file there), made with `Vault.createFolder` (1.4.0) where it is missing.
- **The name** is the device's file name, with the characters Obsidian does not take in a name (`\ / : * ? " < > |`) replaced by `-`; where a file or folder of that name is there, a number is added before the extension, `photo 1.jpg`, `photo 2.jpg`, as Obsidian numbers its own copies. `FileManager.getAvailablePathForAttachment` (1.5.7) is not used: it follows the reader's attachment settings, not this folder; `Vault.getAvailablePath` is not in the public API.
- **The order.** The path and the format are checked first, against the text the card was drawn from (`mediaFileEdit` without applying it); a refusal is shown and nothing is copied. Then the file is read (`File.arrayBuffer()`) and written with `Vault.createBinary` (0.9.7), and only then is the path written, at the version the card was drawn at.

**What a copy leaves behind.** Copying is a write to the vault, made only on the reader's choice of *Upload from device* and of a file in the device's picker. If the write of `FILE` is refused after the copy — the tab's text changed while the file was copied — the copy is left in the vault and the message under the row says where it is and why the line was not changed; the plugin removes nothing of the vault on its own. Removing it would be a second vault write the reader did not ask for, on a file the reader may already use, and the copy is the reader's to keep or delete. A failed copy (`createBinary` throwing) writes nothing to the file and says so.

**Messages.** A refusal, a failed copy and the copy left behind are drawn under the file control, kept in the tree's state for its row as any message is, and said through the live region. A successful write redraws the card; its row shows the new picture.

**The host calls.** `TreeHost` gains `mediaFileAt(line)` and `replaceFile(at, line, done)`; `CardTab` gains `vaultFiles()`, `vaultHas(path)`, `copyIntoVault(path, data)`, `checkFileAt` and `writeFileAt`; `CardView` gains `chooseVaultFile` and `chooseDeviceFile`. `replaceFile` is built in `mediaFile.ts` (`fileChoices`) from those, so the two choices, the folder, the name, the order of checking, copying and writing are tested without Obsidian; `GedcomView` and `harness/desk.ts` are thin. The harness stands in for the vault (a set of paths, a copy that keeps the bytes as a blob URL so the new picture is drawn), for the menu and for the list of files (its chooser of buttons), and uses the real `<input type="file">`, which Playwright answers through its file chooser.

## Implementation

Built against the linked upstream (lavich/domorium main 0dff528), which carries #522 and #527: `setValue` on an opening line writes a note's text with its `CONT` lines, replaces a 5.5.1 `NOTE` with its `CONC` and `CONT`, writes a custom record's value, refuses `INDI` and `HEAD` with `value-not-allowed`, and refuses a stale version with `stale-document`. Where the code departs from the decisions above, or adds to them:

- **`HEADER_ID` lives in the read model.** `src/genealogy/types.ts` defines it, since `buildIndex` keys the header's lines under it; `deskState.ts` re-exports it. `GenealogyIndex` gains `lists` (the ids of the media, notes, repositories and other records), `linkedFrom` and `sourcesOf`; `MediaRecord` gains `form`, which the media's Format column reads. `recordLines` takes the described value as a second argument and sets `xref` only where the opening line has an identifier.
- **The rows of the four new kinds** are `RecordRow`s in `listRows.ts`, built from `lists` on first request and kept per index and language (the Other kind's Kind column is in the reader's words). `recordKind` answers them from a map of those lists, and `pageKind` is now a mapping of `recordKind`, so the two cannot disagree.
- **The probe of the kind buttons is clipped.** An absolutely placed probe at its natural width made the list scroll sideways at 390 px, so the probe is a zero-size element with `overflow: hidden` holding a `.gedcom-list-seg` of the eight buttons at `max-content`, which is what is measured. The sum adds the bar's `column-gap`, and the search icon's width is remembered from when it was last shown, since the open search hides it.
- **`place()` switches a holding kind on a later reveal.** Besides a fresh selection and a card-origin one, a selection already marked switches the list when it is brought into view and its kind is one of the five holding kinds (`fresh || (kind !== this.kind && (fromCard || HOLDING.has(kind)))`). Without it, a medium marked while the list was shown without a reveal would never switch the Notes to the Media, which task 3.3 tests.
- **`routeRecord`'s `declared` answers a position**, where the file starts the record, rather than whether it declares one, so the Source route carries where to put the cursor and `GedcomView` no longer looks the record up again.
- **Whether a root has a field is asked through a new host call, `holdsValueAt`**, on `TreeHost` and `CardTab`, implemented in `addableFields.ts` as `describeStructure(at).payload.kind !== "none"` and wired in `GedcomView` and `harness/desk.ts`. Where the card does not write, a note's root shows its text folded and a custom record's root a read-only field.
- ***Open note* uses Obsidian's `sticky-note` icon**, and is placed before the note's own lines so it stands beside the text; on a coarse pointer and `.is-mobile` it takes the 44 px of the place control. The harness gains the icon.
- **Fixtures.** `curieWithPlan()` in `src/testing/curie.ts` (a `@P1@ _PLAN Custom value` named *Research plan*) is offered to both harnesses as `plan: true`. The 5.5.1 file with a `SUBN` is written in the unit tests and the specs themselves and passed as `doc`, since it needs nothing of the demo file.
- **The empty state** counts people, families and sources that have an identifier, as the spec words it, where it counted any row before.
- **Seen in the screenshots, left as they are:** the header's `GEDC` and `VERS` lines show their tags, and its `SOUR` (the producing system) reads *Source*, because the tree names tags without regard to where they stand and the catalogues have no words for these; on a phone the note pointer's text column is narrow beside *Open note*, the pointer list and the bin.
